## Upgrade hypothesis and gate

The [historical adapter](https://raw.githubusercontent.com/msabramo/requests-unixsocket/8449bc0f76a2ce410644b5e8aab45829ddca54f7/requests_unixsocket/adapters.py) overrides `get_connection` only. [Requests history](https://github.com/psf/requests/blob/main/HISTORY.md) states that custom `HTTPAdapter` implementations need to migrate to `get_connection_with_tls_context` for Requests 2.32.2 and later. [Current upstream adapter](https://github.com/msabramo/requests-unixsocket/blob/master/requests_unixsocket/adapters.py) includes that method. A dependency-only upgrade from a pre-2.32 release to 2.32.2 or later may therefore route Unix-socket requests through the default adapter connection path and fail. This is a hypothesis, not an observed failure or a validated repair. The historical adapter also constructs its pool connections from `http.client.HTTPConnection`; urllib3 version compatibility needs its own test.

Gate G1 requires a passing original baseline, a real dependency-only result, and a manually understood reference repair in distinct disposable containers on Vultr. Record exit codes, collected IDs, JUnit XML, installed versions, exact wheel hashes, container cleanup, and source/image digests. Until those exist, `profiles/requests-unixsocket/research.json` remains disabled and must not appear among executable examples. Local Docker has a client but no reachable daemon, so no local container result exists.
