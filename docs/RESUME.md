The bounded exec transport from commits `c54ad64` and `31ae613` is unchanged in shape: staged input is written to the standard input of a fixed `python -I -c` script as an 8-byte little-endian length frame with `O_EXCL` targets, attempt input is unpacked by a tarfile data-filter extraction exec, and exports are read back as `O_NOFOLLOW` regular files demultiplexed by a `_FrameDemuxer` that parses Docker's non-TTY stream framing (8-byte `>BxxxL` headers) before validation. Every Docker and socket call is bounded by a monotonic deadline, and `DeadlineExceeded` maps to a timed-out status with a guarded kill, log capture, and observed removal.

The second experiment attempt failed at preparation, and the failure is kept as an honest record in `/root/upgrade-chamber-evidence/g2-012326e-1/summary.json` (overall status "stopped"; the evidence directory is untouched). The first staging exec issued about 65 ms after `container.start()` raced the containerd init process of the bridge-networked container, which docker-py surfaced as an APIError containing `FailedPrecondition: container init process is not running`; the recorded surfaced error was "RuntimeError: Staging exec failed with exit code None for /work/ready" with preparation elapsed 0.38s and removal observed. Fix commit `9df41cb` adds a `_start_exec` helper in `src/upgrade_chamber/runner.py` that performs the `exec_create`/`exec_start(socket=True, tty=False)` pair and retries it when, and only when, the raised exception is named `APIError` (matched by type name, without importing docker, the same way `NotFound` is matched) and its message text contains "FailedPrecondition" or "not running". The retry is bounded to 5 attempts with a 0.25s sleep between attempts, each retry is checked against the run deadline via `_remaining_seconds`, any stream from a failed attempt is closed, and any other exception propagates unchanged. `_exec_write_file`, `_exec_extract_tar`, and `_exec_read_file` are all routed through the helper with their framing, demuxer, exit-code mapping, and deadlines unchanged. Three new fake-client tests cover one failure then success, five consecutive failures surfacing as a `RuntimeError` after exactly 5 `exec_create` attempts, and a non-precondition APIError propagating after a single attempt.
