## Deployment topology

- `upgrade-chamber-api` runs as `upgrade-chamber:upgrade-chamber` (no Docker group membership) and listens on `127.0.0.1:8000` only. It holds `VULTR_INFERENCE_API_KEY` and `VULTR_MODEL_ID` (`minimax-m3`) in `/etc/upgrade-chamber/api.env` (mode `0600`, `root:root`); the key never reaches the worker or any container.
- `upgrade-chamber-worker` runs as the `upgrade-chamber-worker` user (primary group `upgrade-chamber`, Docker group membership, no inference key) from `/etc/upgrade-chamber/worker.env` (mode `0640`, `root:root`, database/artifact/image settings only, never credentials), leasing runs from the shared SQLite state at `/var/lib/upgrade-chamber/runs.db` (`0660`, owned `upgrade-chamber:upgrade-chamber`; the state directory and `artifacts/` stay `0770`).
- Both systemd units harden with `NoNewPrivileges=yes`, `PrivateTmp=yes`, and `ProtectSystem`; `INTERNAL_TOKEN` guards the internal endpoints (401 without the header).
- Caddy serves the public `https://45.76.66.244` (self-signed certificate, disclosed to reviewers) and proxies to the API; the deployed frontend bundle is `index-13yOF-NI.js` (commit `ef34617`), verified live over HTTPS in the final sweep.
- The VM runs Ubuntu 24.04, Docker 29.8.1, and uv 0.11.8 at `/opt/uv-0.11.8/bin/uv`.

## Standing rules

Never print or commit `.env` or `.local` contents, the inference API key, `INTERNAL_TOKEN`, or per-run tokens (ignored `.local/infra/state.json` records the VM and inference IDs and SSH paths; ignored `.env` holds the inference key and model ID). Never destroy VM resources, backups, evidence directories, or the runner image — both Vultr resources remain billable until explicitly directed otherwise. Deployment archives stay allowlisted and exclude `.env`, `.local`, credentials, and tests. Report failures honestly; no overclaiming and no fabricated counts. The `/opt/upgrade-chamber` installation keeps its fingerprint guard, so plan and review any further source replacement rather than assuming a bootstrap rerun will deploy it. New upgrade runs go through the public API (`POST /api/runs` on `127.0.0.1:8000`, rate-limited to ten submissions per rolling hour per IP (raised from three; queue cap and serial worker remain the real throttles)) and are processed by the worker; the operator script (`scripts/run_experiment.py`) remains for containment-style probes.
